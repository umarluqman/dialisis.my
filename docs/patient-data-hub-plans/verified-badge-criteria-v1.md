# `Verified` Badge Criteria + Review SOP (v1)

Date: 2026-02-24
Status: Draft for pilot / pre-launch
Purpose: Define objective, patient-first criteria for the `Verified` badge

## 1) Positioning

`Verified` replaces `Pilihan Utama`.

Meaning:

- `Verified` indicates objective checks passed
- `Verified` does not mean paid ranking or recommendation
- `Verified` should help patients trust the listing information

If paid placement exists later:

- Use a separate label such as `Sponsored`
- Never substitute `Verified` for paid placement

## 2) Badge Eligibility (High Level)

A center may be eligible for `Verified` if it:

- Can be identified as a real dialysis center/branch
- Has verified contact channels
- Provides complete, accurate basic profile information
- Agrees to maintain listing accuracy
- Agrees to receive/respond to patient-authorized digital transfer handoffs (for subscribed centers)

## 3) v1 Criteria Checklist (Objective)

### A) Identity and branch validity

- [ ] Center/branch name confirmed
- [ ] Branch location/address confirmed
- [ ] Branch belongs to a real operating entity (basic business/organization check)
- [ ] No obvious duplicate listing conflict (or conflict resolved)

Required evidence (v1):

- Public listing / official website / branch document / operator confirmation

### B) Contact channel verification

- [ ] Primary phone number verified
- [ ] WhatsApp number verified (if listed)
- [ ] Email verified (if listed)
- [ ] Receiving contact role identified (nurse/coordinator/admin/manager)

Required evidence (v1):

- Successful callback, verified response, or official channel confirmation

### C) Basic profile completeness

- [ ] Center description present
- [ ] Address/location details present
- [ ] Operating hours present (or clearly marked unavailable)
- [ ] Contact methods present
- [ ] Core services/facilities information present
- [ ] Last updated date recorded

Rule:

- `Verified` should require completeness of core patient-facing information, not perfect marketing content.

### D) Accuracy and maintenance commitment

- [ ] Center confirms listing information is accurate at time of verification
- [ ] Center agrees to update changes (hours/contact/services)
- [ ] `dialysis.my` can remove `Verified` if information becomes inaccurate

### E) Digital transfer workflow readiness (subscription-linked)

For centers using the paid workflow access:

- [ ] Center has an identified receiving contact for transfer/intake packets
- [ ] Center agrees to secure receipt of patient-authorized digital handoffs
- [ ] Center understands `Verified` is separate from ranking/promotion

## 4) Pass / Fail Decision (v1)

Recommended v1 decision rule:

- Pass only if sections A, B, C, and D are all complete
- Section E applies only when the center is using subscription workflow access

Possible outcomes:

- `Verified` approved
- Pending (missing items)
- Rejected (failed verification)
- Revoked (previously verified but no longer compliant)

## 5) Review SOP (v1)

### Step 1: Intake

- Create verification review record for the center/branch
- Assign reviewer
- Collect available public listing/profile data

### Step 2: Evidence collection

- Check branch identity and location
- Verify contact channels
- Review profile completeness
- Record evidence source and date

### Step 3: Center confirmation

- Contact center representative
- Confirm accuracy of core listing information
- Confirm maintenance commitment
- Explain `Verified` meaning (not paid ranking)

### Step 4: Decision and publishing

- Mark outcome (`approved`, `pending`, `rejected`)
- If approved, publish `Verified` badge
- Record approval date and reviewer
- Schedule next review date

### Step 5: Re-check / revocation

Triggers for re-check:

- Patient reports wrong contact info
- Delivery failures / repeated unreachable contact
- Center requests updates
- Internal QA spot check

Revocation rule (v1):

- Remove `Verified` if core contact/location information is repeatedly inaccurate and not corrected in a reasonable time

## 6) Evidence to Store (v1)

Store enough proof for internal audit:

- Reviewer name
- Review date
- Sources checked (website, call, email, directory)
- Contact verification notes
- Outcome and reason
- Next review date

Do not store unnecessary sensitive personal data in the verification record.

## 7) Suggested Review Cadence

Recommended v1:

- Initial verification before badge is shown
- Light re-check every 6 months
- Immediate re-check on major change reports (contact/address issues)

## 8) Patient-Facing Badge Copy (Draft)

Short label:

- `Verified`

Tooltip / helper copy:

- "`Verified` means this center's core listing details and contact channels were checked by `dialysis.my`. It does not mean paid placement or medical recommendation."

## 9) Operational Notes

- `Verified` can be available to subscribed centers, but the criteria must remain objective.
- If non-subscribed centers are later allowed to apply for `Verified`, use the same criteria.
- Keep badge rules consistent across branches to avoid bias perception.

## 10) Pilot Decisions To Finalize

- Who can approve/revoke `Verified`
- Minimum evidence standard for identity/business checks
- Re-check cadence (3 months vs 6 months)
- Whether `Verified` is shown only after subscription at launch, or later expanded
- Exact patient-facing badge tooltip copy (BM and English)
